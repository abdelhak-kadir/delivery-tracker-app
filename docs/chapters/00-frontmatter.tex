% ---------------- Abstract ----------------
\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}
\markboth{Abstract}{}
This report presents the Delivery Tracker project, carried out during a one-month final-year internship at Youssra Trans-N\'egoce, a transport company. The company needs to record its clients, drivers and transport logs reliably, and the project goes beyond the application itself: the code is delivered through a pipeline in which security is verified at every stage, following DevSecOps principles. We built a Spring Boot REST API secured with JSON Web Tokens, a React single-page frontend and a PostgreSQL database, packaged in non-root Docker images. The infrastructure on DigitalOcean is described with Terraform, servers are configured with Ansible, and GitHub Actions workflows chain build, tests, secret detection, static analysis, dependency and image scanning, and Open Policy Agent rules checked against the Terraform plan.

The evidence collected at the end of the internship shows 82 passing backend tests with 77.1\,\% line coverage, no finding from Semgrep on the application code, unauthenticated requests rejected with HTTP 401, and images of 353\,MB and 70.1\,MB. It also shows the limits of the work: a single administrator account, report-only auditing of frontend dependencies, a Terraform workflow that never succeeded on the remote repository, and Ansible roles not yet executed against real servers. A review of our own implementation corrected several pipeline defects, such as gates that could not fail and policies that could not match. We conclude with a prioritized list of future work.

\textbf{Keywords:} DevSecOps, CI/CD, GitHub Actions, Spring Boot, JWT, Docker, Terraform, Ansible, Open Policy Agent, security scanning, Infrastructure as Code.

\begin{otherlanguage}{french}
\chapter*{Résumé}
\addcontentsline{toc}{chapter}{Résumé}
\markboth{Résumé}{}
Ce rapport pr\'esente le projet Delivery Tracker, r\'ealis\'e lors d'un stage de fin d'\'etudes d'un mois chez Youssra Trans-N\'egoce, une entreprise de transport. L'entreprise a besoin d'enregistrer de fa\c con fiable ses clients, ses chauffeurs et ses bons de transport. Le projet ne se limite pas \`a l'application : le code est livr\'e par une cha\^ine dans laquelle la s\'ecurit\'e est v\'erifi\'ee \`a chaque \'etape, selon les principes DevSecOps. Nous avons r\'ealis\'e une API REST Spring Boot s\'ecuris\'ee par des jetons JSON Web Token, un frontend React en application monopage et une base PostgreSQL, empaquet\'es dans des images Docker sans privil\`eges root. L'infrastructure sur DigitalOcean est d\'ecrite avec Terraform, les serveurs sont configur\'es avec Ansible, et des workflows GitHub Actions encha\^inent la compilation, les tests, la d\'etection de secrets, l'analyse statique, l'analyse des d\'ependances et des images, ainsi que des r\`egles Open Policy Agent v\'erifi\'ees sur le plan Terraform.

Les mesures recueillies \`a la fin du stage montrent 82 tests backend r\'eussis avec 77,1\,\% de couverture de lignes, aucune alerte de Semgrep sur le code de l'application, des requ\^etes non authentifi\'ees rejet\'ees par un code HTTP 401, et des images de 353\,Mo et 70,1\,Mo. Elles montrent aussi les limites du travail : un seul compte administrateur, un audit des d\'ependances frontend en simple rapport, un workflow Terraform qui n'a jamais r\'eussi sur le d\'ep\^ot distant, et des r\^oles Ansible non encore ex\'ecut\'es sur de vrais serveurs. Une revue de notre propre impl\'ementation a permis de corriger plusieurs d\'efauts de la cha\^ine, comme des contr\^oles qui ne pouvaient pas \'echouer et des politiques qui ne pouvaient pas s'appliquer. Nous concluons par une liste de travaux futurs class\'es par priorit\'e.

\textbf{Mots-cl\'es :} DevSecOps, CI/CD, GitHub Actions, Spring Boot, JWT, Docker, Terraform, Ansible, Open Policy Agent, analyse de s\'ecurit\'e, infrastructure en tant que code.
\end{otherlanguage}
