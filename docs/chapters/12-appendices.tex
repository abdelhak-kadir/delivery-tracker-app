\section{API Endpoints}

All business endpoints are served under the prefix \texttt{/api/v1}, built from the constants of \texttt{ApiPaths}. The application has a single role (\texttt{ROLE\_ADMIN}), so ``JWT'' in the third column of Table~\ref{tab:app-endpoints} means any request carrying a valid bearer token. Successful answers are wrapped in a \texttt{BaseResponse}, and list endpoints return a \texttt{PagedResponse}. Pagination uses the query parameters \texttt{page} (default 0) and \texttt{size} (default 10; at most 100 for clients and drivers, at most 30 for transport logs).

\section{CI/CD Workflow Excerpts}

The excerpts below are shortened; ``\texttt{...}'' marks omitted lines. They are taken from \texttt{.github/workflows/}.

\begin{lstlisting}[language=YAML, basicstyle=\ttfamily\scriptsize, caption={Backend CI: jobs and their dependencies (\texttt{ci-back.yaml})}, label={lst:wf-ci}]
on:
  push:
    branches: ["**"]
    paths: ['back/**', '.github/workflows/**']
  pull_request:
    branches: [main]
    paths: ['back/**']
jobs:
  build:
    steps:
      - uses: actions/setup-java@v4
        with: { java-version: '21', distribution: 'temurin' }
      - run: ./mvnw clean install
        working-directory: ./back
  test:
    needs: build
    steps:
      - run: ./mvnw test            # JaCoCo report generated by the Maven plugin
        working-directory: ./back
      - uses: codecov/codecov-action@v4
  build-and-push-docker:
    needs: [build, test]            # image tagged <sha>-staging, pushed to ghcr.io
  security-scans:
    uses: ./.github/workflows/security-scans.yaml
    needs: [build, test, build-and-push-docker]
\end{lstlisting}

\begin{lstlisting}[language=YAML, basicstyle=\ttfamily\scriptsize, caption={Backend security scans: the gating steps (\texttt{security-scans.yaml})}, label={lst:wf-sec}]
      - name: Run Gitleaks (Secrets Detection)
        uses: gitleaks/gitleaks-action@v2
      - name: Run OWASP Dependency-Check (SARIF)
        uses: dependency-check/Dependency-Check_Action@main
        with:
          path: './back'
          format: 'SARIF'
          args: >
            --failOnCVSS 7
            --enableRetired
      - name: Trivy FS Gate (fail on CRITICAL)
        run: trivy fs --offline-scan --exit-code 1 --severity CRITICAL --ignore-unfixed .
      - name: Fail if HIGH/CRITICAL vulnerabilities found
        run: trivy image --exit-code 1 --severity HIGH,CRITICAL "$IMAGE_TAG"
\end{lstlisting}

\begin{lstlisting}[language=YAML, basicstyle=\ttfamily\scriptsize, caption={Terraform workflow: scans, plan and policy check (\texttt{terraform.yaml})}, label={lst:wf-tf}]
  plan:
    name: Security Scan + Plan
    if: github.event_name != 'schedule'      # scheduled runs only detect drift
    steps:
      - uses: aquasecurity/tfsec-action@v1
      - uses: bridgecrewio/checkov-action@master
        with: { directory: infra, framework: terraform }
      - run: terraform init
      - run: terraform validate
      - name: Terraform Plan (save JSON for OPA)
        run: |
          terraform plan -out=tfplan
          terraform show -json tfplan > tfplan.json
      - name: Run Conftest on Terraform plan
        run: conftest test --policy policy --namespace terraform.security tfplan.json
  apply:
    needs: plan
    if: github.ref == 'refs/heads/main' &&
        (github.event_name == 'push' || github.event_name == 'workflow_dispatch')
\end{lstlisting}

\begin{lstlisting}[language=YAML, basicstyle=\ttfamily\scriptsize, caption={OPA policy check on pull requests (\texttt{opa-policy-check.yaml})}, label={lst:wf-opa}]
    env:
      HAS_TF_TOKEN: ${{ secrets.TF_API_TOKEN != '' }}
    steps:
      - run: opa check policy/               # always runs
      - run: opa test policy/ -v             # 11 unit tests, no credentials needed
      - name: Terraform Plan                 # only when TF_API_TOKEN is set
        if: env.HAS_TF_TOKEN == 'true'
        run: terraform plan -out=tfplan.binary
      - name: Run OPA on the plan
        if: env.HAS_TF_TOKEN == 'true'
        run: opa eval --format pretty --fail-defined -i plan.json -d policy/
             "data.terraform.security.deny[_]"
\end{lstlisting}

The backend CD workflow (\texttt{cd-back.yaml}) is triggered when the Terraform workflow completes successfully and connects to the server over SSH to run \texttt{docker compose pull} and \texttt{docker compose up -d}; the frontend CD workflow is a placeholder, as stated in Chapter~\ref{chap:discussion}.
